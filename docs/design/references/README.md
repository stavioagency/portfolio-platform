# Reference analyses

Each file analyses **why a product works**, not what it looks like.

The test for a line in these files: it must be a principle that survives being
stripped of the product's visual identity. "Linear has a command palette" is
worthless. "Linear puts the whole product one keystroke away so navigation
never costs a decision" is usable.

Every file ends with two sections that matter more than the rest —
**what Designakum should learn** and **what Designakum must not copy.** A
reference without a stated boundary becomes an imitation.

- [lumetra.md](lumetra.md) — the operator product; nearest structural analogue
- [apple.md](apple.md) — restraint, defaults, and the product as a frame
- [linear.md](linear.md) — opinion, speed, and state as vocabulary
- [framer.md](framer.md) — creative tools, and the builder trap to avoid
